# SQL 文件管理规范

> 适用范围：`sql/` 目录下所有**新增** SQL 文件（建表、表变更、索引、初始数据、数据订正等）。
> 表结构、字段、索引的**设计**规范见 [skills/design/db-designer.yaml](../skills/design/db-designer.yaml)，本规范只规定文件「放在哪个目录、如何命名」。
> AI 生成 SQL 文件时必须遵循本规范。

## 1. 目录规则

新增 SQL 文件时，**必须先确认发版日期**，按以下优先级确定存放目录：

| 优先级 | 场景 | 目录 | 示例 |
|:---:|------|------|------|
| 1 | 已指定发版日期 | `sql/{发版日期}/` | `sql/2026_10_20/` |
| 2 | 未指定发版日期，归属单一模块或业务域 | `sql/{模块名}/` | `sql/mes/`、`sql/za/` |
| 3 | 未指定发版日期，无法归属单一模块（跨模块、通用脚本） | `sql/{当前日期}/` | `sql/2026_10_14/` |

规则：

1. 日期目录格式为 `YYYY_MM_DD`（下划线分隔），发版日期目录与当前日期目录格式一致。
2. 模块名 / 业务域使用小写编码：模块编码以 `docs/` 下实际存在的模块目录为准（`system`、`infra`、`pay`、`member`、`mall`、`crm`、`erp`、`bpm`、`ai`、`iot`、`mp`、`report`、`im`、`mes`、`wms`、`fms`、`oa`、`hrm`、`pms` 等）；自定义业务域直接使用业务域编码（如 `za` 治安、`xz` 行政、`jz` 建筑、`ye` 育儿、`wb` 网吧）。
3. 待发布脚本确定发版日期后，移动至对应 `sql/{发版日期}/` 目录；移动时**文件名不变**（文件名日期 = 编写日期，见第 2 节）。当前日期目录名恰好等于发版日期时无需移动。
4. 发版执行时仅取用 `sql/{发版日期}/` 内的文件，按文件名字典序执行；未随版执行的脚本移回所属模块 / 业务域目录。
5. **目录状态**：日期目录在发版执行完成前为「待发布」，可新增、移动、删除其中文件；发版执行完成后即为「已归档」，禁止增删改任何文件，后续变更一律新增文件（新日期）。无法确认发版状态时，目录日期早于当前日期的日期目录一律按已归档处理。
6. **作废脚本**：未归档的作废脚本直接删除，并在提交说明中注明原因与替代文件（如有）；已归档目录中的文件不得删除，需抵消其效果时按新日期新增反向脚本。

## 2. 文件命名规则

```text
{YYYY_MM_DD}-{表名}-{操作}[-{两位序号}][-{数据库标识}].sql
```

| 组成 | 格式 | 说明 | 示例 |
|------|------|------|------|
| 日期 | `YYYY_MM_DD` | SQL 编写日期，确定后不随目录移动改变 | `2026_10_14` |
| 表名 | 小写字母、数字、下划线（`[a-z0-9_]`），以字母开头 | 该 SQL 操作的主表；无单一主表时用功能名 | `mes_process` |
| 操作 | 小写下划线短语（动词_对象），语义参照操作词表 | 词表非穷举，允许自拟 | `create_table` |
| 两位序号（可选） | `01` ~ `99` | 同批无法用操作描述区分的变更，同批文件统一编号 | `02` |
| 数据库标识（可选） | 与 `sql/` 既有方言目录名一致 | 仅方言变体文件使用，恒为最后一段 | `postgresql` |

**分隔符规则**：各段之间用连字符 `-` 分隔；每段内部（日期、表名、操作说明）用下划线 `_` 连接。序号在前、数据库标识恒为最后一段，如 `2026_10_14-mes_process-add_column-02-postgresql.sql`。

### 操作词表

| 操作 | 用途 |
|------|------|
| `create_table` | 新建表 |
| `drop_table` | 新建表的反向操作，破坏性 |
| `add_column` | 新增字段 |
| `modify_column` | 修改字段类型 / 注释 / 默认值 |
| `drop_column` | 删除字段，破坏性 |
| `rename_table` | 表重命名 |
| `rename_column` | 字段重命名 |
| `add_index` | 新增索引 |
| `drop_index` | 删除索引 |
| `truncate_table` | 清空表数据，破坏性 |
| `insert_data` | 初始数据（菜单、字典等） |
| `update_data` | 数据订正，破坏性 |
| `delete_data` | 数据清理，破坏性 |
| `create_view` | 创建视图 |

- **破坏性操作**（`update_data`、`delete_data`、`drop_table`、`drop_column`、`truncate_table`）：文件头必须附回滚说明或执行前备份前提。
- 词表非穷举：未覆盖的操作按 `动词_对象` 自拟（小写下划线），不要求以词表词开头，如 `add_tenant_id_column`、`insert_menu_data`。
- 需独立回滚脚本时，操作段用 `rollback_` 前缀 + 被回滚操作，如 `rollback_drop_column`。
- **方言变体**：默认编写 MySQL 主文件（不带标识）；仅当语句不兼容时创建方言变体文件（除末尾标识外与主文件同名）。同一变更的各方言文件互为替代——每个数据库只执行其一，不参与跨变更排序。标识取值与 `sql/` 既有方言目录一致：`mysql`、`postgresql`、`oracle`、`sqlserver`、`dm`、`kingbase`、`opengauss`、`oceanbase`、`highgo`、`db2`。

### 命名示例

| 文件名 | 含义 |
|--------|------|
| `2026_10_14-mes_process-create_table.sql` | 新建 mes_process 表 |
| `2026_10_14-mes_process-add_priority_column.sql` | mes_process 新增 priority 字段 |
| `2026_10_13-system_dict_data-insert_data.sql` | 新增字典初始数据（system 模块） |
| `2026_10_14-za_case-create_table-postgresql.sql` | 治安案件表的 PostgreSQL 方言变体 |

### 冲突与执行顺序

- **执行顺序 = 文件名字典序**：先按日期、再按表名、最后按操作名排序。
- 同一天、同一表多次变更：优先用更具体的操作描述区分（如 `add_priority_column` / `add_category_column`）；仍无法区分时，**同批文件统一追加两位序号**（`-01`、`-02`……），保证字典序与执行序一致。
- 文件以本次变更的**主表**命名；表结构变更（DDL）原则上按表拆分；初始数据 / 数据订正类脚本允许以主表命名覆盖多表写入，文件头注明涉及的其他表。

## 3. 文件内容要求

1. 每个文件一个变更单元，文件头包含注释块（日期行用 `YYYY-MM-DD` ISO 格式，仅用于注释；文件名与目录仍用 `YYYY_MM_DD`）：

```sql
-- ============================================
-- 文件名：2026_10_14-mes_process-add_priority_column.sql
-- 说明：mes_process 新增 priority 字段
-- 作者：{姓名}
-- 日期：2026-10-14
-- 关联需求：{需求号，如有}
-- 回滚说明：{回滚语句或备份方式，破坏性操作必填}
-- ============================================
```

2. 优先保证脚本可重复执行（`IF EXISTS` / `IF NOT EXISTS`）；数据库不支持的语句，在文件头注明执行前提。
3. 字段、索引设计遵循 [db-designer.yaml](../skills/design/db-designer.yaml)（必需 `tenant_id`、审计字段，索引首列 `tenant_id` 等）。
4. 文件编码 UTF-8；SQL 关键字大写，表名 / 字段名小写。反引号仅用于 MySQL 及其兼容库脚本，其他数据库变体按各自方言引用标识符。

## 4. 目录结构示例

```text
sql/
├── 2026_10_20/                                 # 已指定发版日期（发版执行前可调整）
│   ├── 2026_10_14-mes_process-create_table.sql
│   └── 2026_10_15-mes_process-add_priority_column.sql
├── mes/                                        # 未定发版日期，归属 mes 模块
│   └── 2026_10_13-mes_work_order-add_index.sql
├── system/                                     # 未定发版日期，归属 system 模块
│   └── 2026_10_13-system_dict_data-insert_data.sql
├── 2026_10_14/                                 # 未定发版日期，跨模块（无单一归属）
│   └── 2026_10_14-mes_item-update_data.sql     # 跨 mes/wms 物料订正，文件头注明涉及表
├── za/                                         # 业务域目录示例（治安）
│   └── 2026_10_14-za_case-create_table.sql
├── master/                                     # 既有：多数据库全量基线（本地维护）
├── mysql/ … postgresql/ …                      # 既有：源项目各数据库全量脚本
└── tools/                                      # 既有：数据库转换工具
```

## 5. 与既有规范 / 目录的关系

| 对象 | 关系 |
|------|------|
| `sql/master/`（本地维护的多数据库全量基线）、`sql/{db}/`（来自源项目的各数据库全量脚本） | 全量基线，保持不变；新增 SQL 一律按本规范存放，不再写入这些目录 |
| `skills/design/db-designer.yaml` | 表 / 字段 / 索引设计仍以其为准；其文件命名与目录相关条目已同步修订（v1.1.0，2026-10-14）与本规范对齐；后续修改 db-designer.yaml 不得引入与本规范冲突的命名或目录规则 |
