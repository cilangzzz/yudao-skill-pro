## 使用指南概述

本目录提供芋道源码项目的 AI 辅助开发使用场景指南。每个场景文档都包含：

- **适用情况**：什么场景下使用该提示词
- **输入要求**：需要提供哪些信息
- **预期输出**：AI 将生成什么样的代码或文档
- **使用示例**：实际案例演示

### Skills 资源概览

| 资源类型 | 目录位置 | 说明 |
|---------|---------|------|
| 模块代码模式 | `docs/{模块}/code-patterns.md` | 各功能模块的完整技术规范 |
| 设计模式 | `skills/design/patterns/` | 常用设计模式的实现模板 |

## 场景分类

### 一、快速上手

| 场景 | 适用情况 | 文档链接 | 一句话描述 |
|-----|---------|---------|-----------|
| **实体类实现** | 需要从 SQL 到实体类创建完整 CRUD 功能 | [entity-implementation.md](entity-implementation.md) | 从建表到完整接口的端到端指南 |

**推荐使用流程**：

```
阅读 CLAUDE.md 模块列表 --> 选择目标模块 --> 阅读对应 code-patterns.md --> 开始开发
```

---

### 二、扩展模块

适用于在现有模块基础上添加新功能的场景。具体目标模块的「渠道/策略/业务实体」扩展模式见 [extend-module.md](extend-module.md)。

**扩展开发要点**：

1. 阅读目标模块的 skill 文档
2. 理解现有代码结构和命名规范
3. 参考文档中的代码示例
4. 遵循文档中的开发约束

---

### 三、改造模块

适用于修改现有功能或重构代码的场景。分析框架、风险评估与回滚策略见 [refactor-module.md](refactor-module.md)。

**改造开发要点**：

1. 重点阅读对应模块 code-patterns.md 的「核心流程」与「扩展指南」章节
2. 了解模块间的依赖关系
3. 注意数据库字段和索引的影响
4. 遵循向后兼容原则

---

### 四、新增模块

适用于创建全新业务模块的场景。需求分析、架构、数据库、代码、测试全流程见 [new-module.md](new-module.md)。

**新增模块参考**：

参考现有模块的 skill 文档结构：

- 核心模块参考：`docs/modules/system/code-patterns.md`、`docs/modules/infra/code-patterns.md`
- 业务模块参考：`docs/modules/mall/code-patterns.md`、`docs/modules/crm/code-patterns.md`
- 技术模块参考：`docs/modules/bpm/code-patterns.md`、`docs/modules/ai/code-patterns.md`

**新增模块步骤**：

1. 参考现有模块的 `code-patterns.md`（如 `docs/modules/system/code-patterns.md`）确定文档结构
2. 参考现有模块文档提取技术规范
3. 按照模块规范编写代码
4. 更新 CLAUDE.md 模块列表与 docs/README.md 总索引

---

### 五、设计模式应用

适用于需要使用设计模式优化代码结构的场景。多渠道系统的设计模式组合指南见 [pattern-usage.md](pattern-usage.md)。

**设计模式选择指南**：

```
是否需要创建对象? --> 多种类型 --> 工厂模式
                     |
                     v
是否需要切换算法? --> 多种策略 --> 策略模式
                     |
                     v
是否需要固定流程? --> 流程相同，细节不同 --> 模板方法模式
```

---

### 六、菜单权限配置

适用于为后台管理系统新增菜单与按钮权限的跨场景操作（单实体扩展、新增模块、临时补充菜单）。

> 详见 [menu-permission.md](menu-permission.md)

**核心要点**：

1. 逐级查找父菜单 ID（不要假设父菜单 ID 为某个固定值）
2. 序列插入：菜单（type=2）→ 按钮（type=3），同一事务
3. 权限标识格式：`{模块}:{功能}:{操作}`（query / create / update / delete / export）

## FAQ

### Q1: 如何选择正确的 skill 文档?

**A:** 根据你的开发任务类型选择：

- 快速上手：从 `docs/modules/system/code-patterns.md` 或 `docs/modules/infra/code-patterns.md` 开始
- 扩展功能：选择对应业务模块的 skill 文档
- 改造功能：重点阅读对应模块的"核心流程"部分
- 新增模块：参考 `docs/modules/system/code-patterns.md` 等现有模块文档作为模板

### Q2: skill 文档包含哪些内容?

**A:** 标准文件结构（README / api-{domain} / data-model / code-patterns / pitfalls）见 [CLAUDE.md](../../CLAUDE.md) `## 模块功能文档 / 通用结构` 一节。

### Q3: 如何使用设计模式文档?

**A:** 设计模式文档提供：

1. 模式的概念和适用场景
2. 项目中的实际应用案例
3. 代码实现模板
4. 使用注意事项

当你需要优化代码结构或解决特定设计问题时，参考对应的设计模式文档。

### Q4: 如何创建新的 skill 文档?

**A:** 创建新模块的 skill 文档步骤：

1. 参考现有模块的 skill 文档（如 `docs/modules/system/code-patterns.md`）作为模板与示例
2. 按照现有文档结构填写模块信息
3. 更新 CLAUDE.md 模块列表与 docs/README.md 总索引

### Q5: 如何理解模块之间的依赖关系?

**A:** 模块依赖关系：

```
system (系统管理) <-- 几乎所有模块都依赖
     |
     +-- member (会员) <-- mall, crm
     |
     +-- infra (基础设施) <-- 所有模块
     |
     +-- pay (支付) <-- mall, member
```

开发时注意：

- system 模块提供用户、权限等基础能力
- infra 模块提供文件、配置、任务等基础服务
- 业务模块之间可能存在依赖关系

### Q6: 如何快速找到某个功能的实现位置?

**A:** 使用 skill 文档的"目录结构"和"核心流程"部分：

1. 在 skill 文档中查找对应功能的目录位置
2. 阅读"核心流程"了解实现逻辑
3. 参考"代码示例"找到具体实现

### Q7: 文档中的代码示例可以直接使用吗?

**A:** 可以，但需要注意：

1. 代码示例遵循项目规范，可作为模板
2. 使用前需要根据实际业务需求调整
3. 注意替换示例中的占位符和示例数据
4. 建议先在测试环境验证
